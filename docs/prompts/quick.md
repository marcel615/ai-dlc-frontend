# Quick Prompts

상세 절차와 승인 경계는 `.agents/skills/issue-driven-dev/SKILL.md`와 `AGENTS.md`를 따른다.
아래 문구는 예시이며 같은 뜻의 자연스러운 지시도 사용할 수 있다.
공통 명세는 `ai-dlc.yaml`의 활성 서비스 `requirements`, `contracts.api`, `contracts.authentication`(설정된 경우), `contracts.erd`, `contracts.ui`가 지정한 Specs 저장소의 공식 원본을 읽기 전용으로 확인한다.
Main은 품질 게이트를 확인하고 승인된 Issue 범위에서 진행한다.
사용자 판단이 필요한 상황과 PR merge는 사용자에게 남긴다.
일반 개발에서는 공식 계약과 AI-DLC 운영 파일(README.md 제외)을 수정하지 않는다. README.md는 승인된 작업 범위 안에서 수정할 수 있다. 인증 계약의 별도 설정 여부와 확인 실패·충돌 시 처리는 AGENTS.md를 따른다. 현재 설계·작업 기록·Skill별 상태 파일은 기존 책임과 승인 범위에서 수정한다.

## Issue와 설계

- 시작: `Issue #번호 작업 시작해.`
- 다음 Issue 선정: `작업 시작해. 다음 Issue를 확인해줘.`
- 기능 후보: `이 아이디어를 GitHub Project의 승인 대기 후보로 추가해줘.`
- 백로그 정제: `승인한 기능 후보의 백로그를 정제해.` (조건을 충족한 승인된 Draft는 별도 전환 승인 없이 최대 2개를 정식 Issue로 전환한다.)
- Issue 초안 승인: `Issue 초안을 승인하고 GitHub에 등록해.`
- Issue 수정 승인: `Issue 수정안을 승인하고 반영해.`
- 상태 확인: `현재 작업 상태와 품질 게이트 결과를 알려줘.`
- 예외 확인: `멈춘 이유와 내가 결정해야 할 사항을 알려줘.`

## 종료와 중단

- 정리: `PR 머지했어. 확인 후 기준 브랜치 최신화와 브랜치 정리를 진행해.`
- 중단: `작업을 멈추고 현재 상태와 남은 작업을 알려줘.`

## 계약 검토와 AI-DLC 유지보수

- 계약 변경 필요성 검토: `기존 계약으로 구현 가능한 대안을 먼저 검토하고, 변경이 필요하면 사유·영향·수정안을 보고하고 관련 Issue·PR에 기록해줘. 계약 원본은 수정하지 마.`
- 운영 파일 유지보수: `다음 AI-DLC 운영 파일의 목적·대상·영향을 검토하고 별도 유지보수로 승인 범위 안에서 수정해줘: [목적·대상·영향].`

계약 변경은 별도 계약 관리 절차에서만 수행한다. 위 문구는 Issue 생성·수정, 범위 확장, DB·인증/인가 변경 등 기존 승인 조건이나 품질 게이트를 생략하지 않는다.
